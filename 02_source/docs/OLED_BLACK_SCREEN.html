屏幕黑屏诊断记录与操作

2026-09-23最新结果：GPIO诊断显示成功后，用户也确认了正常游戏版运行正常。 正式v1.0.0沿用这一GPIO发送方式并默认启用蜂鸣器，见游戏操作步骤。下面保留黑屏诊断过程，不需要重复烧录已完成的诊断固件。

已确认的实物情况

2026-09-22，用户确认：

  • 屏幕为微雪2.42英寸SSD1309，未改过SPI/I²C焊接设置。
  • 接着屏幕时D2仍每秒短闪。
  • 在屏幕端测得VCC对GND约3.3V，RST对GND约3.3V。
  • 所有供电断开后重新上电，仍无显示；USB转串口暂未连接。
  • 独立oled_check.hex烧录后，D2每秒双短闪，观察所有阶段屏幕始终黑屏。诊断程序未记录板级故障或SPI发送错误，但全亮命令没有产生可见效果；目前不能认定屏幕已损坏，也未证明命令实际到达屏幕。
  • 断电逐根测量J2-3/4/5/6/7到屏幕DIN/CLK/CS/DC/RST，用户确认均接近0Ω且一一对应。此结果支持排线与接口的直连连续性正常，但不证明芯片已经输出正确的电平变化。
  • 换用oled_check_gpio.hex后用户确认画面正常周期变化，低速GPIO发送路径通过实物验证；原硬件SPI失败的具体原因仍未确定。

这些数据支持屏幕接口供电和复位脚稳态电压正常，但不能证明RST曾产生启动复位脉冲，也不能证明CLK、DIN、CS、DC的信号实际到达屏幕。SPI是单向发送，本机发送成功不代表屏幕收到。

使用独立亮屏诊断固件

烧入独立交付目录中的oled_check.hex。沿用已经成功的CubeProgrammer设置，开启烧录校验。烧录后保持屏幕接线不变，重新给主板完整上电，观察至少15秒。

诊断程序沿用游戏版的板级引脚、SPI设置和屏幕初始化，循环显示：

  1. 全亮约2秒：发送SSD1309的A5命令，忽略显存内容。
  2. 黑屏约1秒：发送A4恢复显存显示，写入全黑像素。
  3. 棋盘格约3秒：检查页寻址和数据传输。
  4. 文字与边框约3秒：显示OLED CHECK和SPI / RAM OK，检查实际绘图与显示。

这里的SPI / RAM OK只是测试图案文字，含义是用户实际看见该画面后，才能判断对应路径已工作；固件无法自动知道屏幕是否亮起。

蜂鸣器始终关闭。本程序不运行游戏、声音控制或调音。烧入它会暂时替换游戏，诊断结束后可重新烧回flappy_f103.hex。

看D2和屏幕分别出现什么

观察结果 能说明什么
D2每秒双短闪 诊断入口正在运行，尚未记录板级故障或SPI发送错误；不等于屏幕已连接
D2持续快闪 记录了板级故障或SPI发送失败，下一步读取串口日志定位
全亮能出现，棋盘格/文字不出现 至少部分命令到达且面板能够发光，重点检查DC、数据传输和寻址
全亮、棋盘格和文字都正常 基本显示链路可用，下一步重新检查游戏固件的实际烧录及应用运行
所有阶段始终黑屏 尚不能区分信号未到达、接口配置或模块内部供电/面板问题，继续查接线和波形

如果D2仍是原来的每秒单短闪，先确认是否选中了oled_check.hex、烧录校验是否成功，以及是否重新上电。

如接串口，设115200、8N1。诊断固件自动每秒输出当前显示阶段、SPI_ERR和FAULT，无需发送命令。

元件面朝自己、主板USB在上时，J2在右侧，最下面为1脚，最上面为8脚。

屏幕端按丝印对应，不按排线颜色猜测。调整排线、使用通断或电阻档前断开全部供电；有电时只用电压档。

已完成：检查信号线连续性

拔掉主板、ST-LINK及USB转串口的全部供电，屏幕排线保持连接。用电阻/通断档，直接测主板J2焊点与屏幕对应焊点，避免只测到杜邦线本身而遗漏排母接触或焊点。

主板端 屏幕端 直连接线预期
J2-3 DIN 接近0Ω
J2-4 CLK 接近0Ω
J2-5 CS 接近0Ω
J2-6 DC 接近0Ω
J2-7 RST 接近0Ω

先把两支表笔短接，观察表笔自身电阻；直连线读数应接近这个值。不能只凭蜂鸣档响了就判定良好，部分万用表几十欧姆也会响。

此处只检查正确信号能否从主板接口到达屏幕接口；全部导通仍不能证明芯片引脚发出了正确波形。记录实际结果后，再决定是否需要测时序、接口选择或模块内部供电，不根据黑屏直接更换初始化参数。

已完成：低速GPIO SPI对照

使用独立的oled_check_gpio.hex。它和第一次诊断使用相同接线、主频选择、复位、初始化及全亮/棋盘格流程，只将数据发送改成普通GPIO逐位输出。CLK空闲低、上升沿采样、每字节高位先发；边沿之间增加简单等待，便于和原硬件SPI发送路径进行对照。这个等待不承诺精确频率。

烧录校验成功后完整重新上电，观察至少20秒。正常D2变为每秒三短闪，与第一版的双短闪区分；发生板级故障时仍均匀快闪。蜂鸣器关闭，不需要改接线或接串口。

  • 如果这版可以显示，说明同一屏幕与初始化至少在低速GPIO传输下有效，重点继续定位硬件SPI配置、发送波形和时序；尚不能仅凭这一结果断言是某一项配置错误。
  • 如果仍然黑屏，下一步核对屏幕实物背面的接口选择和内部电源，或使用逻辑分析仪观察信号。继续盲目更换游戏绘图代码没有依据。

软件模拟SPI不读取屏幕应答，三短闪本身不代表屏幕已收到命令。本次有效证据来自用户实际看见全亮、棋盘格和文字；新游戏版本的速度与交互仍需上板确认。

参考与判断边界

初始化已对照微雪官方例程和SSD1309手册，没有找到确定的必要命令缺失。FD 12为解锁，DB 34为手册明确的VCOMH默认设置，不能仅因官方示例用了不同数值就断定黑屏原因。

微雪模块板上有独立升压电路，因此接口3.3V正常并不能证明面板内部驱动电源正常；当前不要求初学者直接测量密集的小元件。
