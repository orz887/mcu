完整游戏版上手步骤

当前已经确认自检D2短闪、GPIO SPI诊断图案，以及等待24次的正常游戏版运行正常。v1.0.0沿用正常版显示方式，默认启用得分与碰撞短音；声音控制保持不变。新音效的实物响声和声学反馈尚待这次烧录确认。

1. 烧入哪个文件

使用发布包中的 firmware/flappy_f103.hex。board_selftest.hex是启动后进入自检页面的版本。

正常游戏版使用已测试正常的24次GPIO等待。如果换接线或模块后出现显示异常，可用firmware/flappy_f103_compat.hex作192次等待的兼容对照，游戏功能相同但画面较慢。两个游戏版的D2均为每秒单短闪。完整教学包内固件位于01_firmware/，独立固件包内位于firmware/。

Windows文件位置：

\\wsl.localhost\Ubuntu-24.04\home\cunyu\outputs\Flappy_Bird_Firmware_v1.0.0_20260923\firmware\flappy_f103.hex

沿用已连接成功的接线与设置：主板USB供电，ST-LINK接GND、SWDIO、SWCLK，ST-LINK的3.3V/5V供电脚留空；CubeProgrammer选SWD、100kHz、Normal、Software reset。

打开“擦除与编程”页面，选择这个HEX，开启烧录校验和烧录后运行，再开始下载。HEX自带地址，无需手动指定。若校验成功后未运行，先断开软件连接，再重新给主板USB上电。不需要操作选项字节或读保护。

2. 开始玩

  1. 上电后保持安静约1.5秒，让程序测量环境底噪。准备界面先显示KEEP QUIET...，完成后显示BLOW TO START。
  2. 对着麦克风短吹一口气，开始游戏，小鸟向上跳。
  3. 每次短吹都会再次上跳；不吹时小鸟逐渐下落。管道向左移动，控制小鸟穿过缺口。
  4. 通过一组管道加1分；碰到管道、顶部或地面后显示GAME OVER与BLOW TO RETRY。
  5. 安静片刻，再短吹一口气重新开始。最高分在本次上电期间保留，断电后清零。

得分和碰撞会短响约60毫秒。为了避免麦克风把蜂鸣器当成吹气，从响声开始有300毫秒的声控屏蔽，随后需要安静片刻再吹。串口发送mute on可关闭游戏音效，mute off恢复；这两个命令不关闭声控。上电和普通上跳不鸣叫。

要使用一口一口的短吹，中间停一下。程序要求声音先回落至少50毫秒，并且两次触发至少间隔180毫秒，持续吹气不会不断上跳。

3. 用串口辅助操作

USB-TTL使用3.3V逻辑，RXD接主板J4的2脚，TXD接3脚，GND接4脚，VCC留空。串口设115200、8N1、无流控；每条命令以换行结束。

想做什么 发送内容
查看采样、门限和当前状态 status
直接开始一局 play
让小鸟上跳一次 flap
暂停 / 继续 pause / resume
返回准备界面 menu
重新测量底噪 cal，随后保持安静约1.5秒
查看自检页面 / 调音页面 diag / tuner

本批主板的SW1–SW4存在触点接法问题，未返修时会被固件屏蔽。当前使用声音开局、上跳和重开，暂停与继续使用串口。BLOCKED=F表示四个故障键已被屏蔽，不会阻塞游戏。

4. 声音不合适时怎么调

先发status查看安静和短吹时的RMS，再把触发门限设在这两个数值之间。例如安静约30、短吹约250，可以先尝试threshold 100。门限调低更灵敏，调高更不容易误触发。

也可以发送pot on，让J5电位器调节门限；发送pot off停止电位器控制。threshold命令会自动关闭电位器控制。修改的门限仅保存在RAM中，重新上电会重新标定。

若安静和短吹时RMS都几乎不变，先检查麦克风与模拟采样；若串口可操作游戏而屏幕黑屏，先检查屏幕供电、7根信号接线和SPI配置。

5. 想改游戏代码时从哪里开始

源码位于发布包的source/目录中：

  • src/main.c：七个任务按顺序运行，是阅读入口。
  • include/app_config.h：集中修改灵敏度、小鸟重力、上跳速度、管道速度和缺口高度。
  • src/core.c：小鸟运动、管道移动、碰撞和计分的具体算法。
  • src/app.c：连接声音、游戏、串口和画面。
  • 新手设计说明：从上电到各模块工作的中文说明及练习。

用户已确认正常游戏版测试正常，本版新增默认音效仍需实物确认。显示驱动每轮最多发送8字节，并跳过未变化区域；这些措施减少主循环单次等待，但不能代替定量帧率和ADC丢块测试。
