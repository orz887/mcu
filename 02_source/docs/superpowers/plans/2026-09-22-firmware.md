# Flappy Bird 固件实施计划

> 使用 executing-plans 的持续执行和记录方法；独立模块并行实现。用户已要求开始开发，按既有功能和硬件继续，不额外提交分支或要求重复授权。

**Goal:** 交付可烧录的自检和声控游戏首版固件及源码。

**Architecture:** STM32Cube HAL 硬件层、纯C算法层、页式显示层、协作主循环。DMA和中断仅搬运/通知，业务处理在主循环。

**Tech Stack:** C11、PlatformIO ststm32 20.0.0、STM32CubeF1、GNU Arm、原生gcc算法验证。

**Spec:** ../../DESIGN.md

## 全局约束

- STM32F103C8T6：64KB Flash、20KB RAM，8MHz外部晶振，保留SWD；不修改硬件、不自动烧录。
- 声控游戏+自检+调音；仅给出已编译和模拟验证范围，不冒称实物验证。
- 不创建 Git 分支或提交；新项目独立目录。用户随后明确要求中文教学注释，优先于原通用“不新增内联注释”规则。
- 固件不能修复 SW1–SW4 硬短路，启动时未释放的按键不得触发动作。
- 所有有界等待均须短且有错误退出；启动屏幕复位采用状态机。

## 重点审查

- 持续低电平按键、DMA滞后/覆盖、无屏幕和无电位器时保持可调试。
- 时间回绕、长按和持续吹气不重复触发事件。
- 普通float优先可读性，调音分步执行以保持采样和串口响应，不做手写定点优化。
- 串口畸形/超长参数不能引发意外命令或内存越界。
- UART/DMA中断共享数据与OLED未发完就改变CS/DC的竞态。
