# 固件验证记录

日期：2026-09-23。对象：带中文教学注释的v1.0.0源码、正常游戏版、兼容游戏版与自检版。

## 已做的检查

- 三个发布环境实际交叉编译成功；项目源文件开启Wall、Wextra、Werror，最终构建未发现警告。
- 原生C测试通过：音频统计、声音触发、启动低电平按键屏蔽、消抖、游戏状态/碰撞/得分、小数坐标边界。
- 调音验证通过：六弦标准音、正负音分、较强二次谐波、衰减声音、静音、削顶、噪声、范围外频率及每轮计算预算。
- 显示驱动验证通过：复位等待、初始化分段后字节序列不变、每轮最多8字节像素或8字节初始化命令、首次完整清屏、刷新期间禁止改帧、边界坐标、文字/缩放、SPI错误后恢复。
- 变化区域发送验证通过：相同画面不发送像素，两处远距离像素修改只发送对应小块并保留其余画面；失败重试或重新初始化后，旧内容记录作废，必须完整清屏。
- GPIO发送验证通过：分别以24和192等待配置捕获上升沿重建1、5、128字节数据，检查mode0、MSB顺序、片选、DC与等待间隔；非法参数不改变引脚。
- 命令验证通过：合法命令、非法参数、超长数字与多余单词。
- 应用回归验证通过：串口丢字不能改变门限；静音立即撤销旧音高；丢ADC块丢弃不连续拼帧；过期采样不能重新发布成有效结果。
- 完整游戏应用流程验证通过：上电标定、吹气开局与上跳、持续响声不连续触发、串口暂停与恢复、通过管道计分、落地结束、再次吹气重开并保留本次上电最高分。模拟四个按键持续接地时，上述流程仍可运行；全程未启动蜂鸣器。音频与硬件接口由测试替身提供，计分和落地场景使用设定位置触发，不代表实物通关测试。
- 上一条静音流程现在先执行明确的mute on。正式默认开音另有回归：开机标定和普通吹气不鸣叫；真实得分/碰撞事件播放4kHz短音；59ms仍响、60ms关闭；300ms屏蔽及重新安静要求防止连续大声造成自触发；mute on及时停音并禁止后续自动音效；tuner停音且拒绝beep。
- ASan/UBSan检查通过。受当前容器限制关闭LSan；业务代码未使用动态内存分配。
- 实际绘图函数导出5种界面的帧缓存，已检查文字布局；docs/screens.png不是实屏照片。
- 发布脚本校验SRAM栈顶、Thumb复位地址、SysTick/DMA/定时器/UART中断向量、64KB/20KB限制、HEX逐行校验和及HEX/BIN内容一致性。
- 压缩包CRC和逐文件SHA256由发布脚本核验。

## 审查中修复的问题

1. 明确启用项目HAL配置头，避免构建工具默认配置覆盖。
2. 串口发送在开中断状态复制数据，只在发布指针时短暂关中断，避免较长输出导致接收丢字。
3. 串口接收丢字后清空未处理队列并等待新的换行，避免将损坏命令解释为另一条合法命令。
4. ADC回调明确标记完成的半区，调试暂停后不依赖回调奇偶推断。
5. 音频不连续时重置调音帧和声音门；静音、超时、削顶时不保留旧的有效调音结论。

## 教学整理后的验证

使用普通float表示游戏位置与速度，RMS直接使用sqrtf，调音直接使用归一化公式和log2f；字库改成可视点阵。重构后重新运行了上述测试和双版本构建。中文注释说明函数职责、字段单位、关键判断和必要的硬件位操作；常用参数集中在app_config.h。

v0.1.1使用一个额外的1024字节数组保存已发送画面，通过每8字节比较跳过相同内容；不引入内存池、RTOS或复杂刷新队列。三个发布固件均核对使用GPIO发送，未链接HAL_SPI_Transmit。

192等待的原诊断一次发送整页，汇编估算会超过16ms音频块间隔，因此不能直接套用到游戏。现在初始化和像素均分小段；正常游戏版等待24次，兼容版保留192次。分片测试证明单次发送字节数有上限，但主循环实际耗时、帧率和丢块仍需实测，不能把电脑测试当成实时性能保证。

## 已有实物反馈及待确认项目

2026-09-22，用户已烧入自检固件并确认D2短闪。随后硬件SPI亮屏诊断仍黑屏；屏端VCC和RST均约3.3V，五根信号线逐根导通且对应正确。

2026-09-23，用户先确认低速GPIO诊断图案显示正常，随后明确反馈等待24次的正常游戏版测试正常。原硬件SPI失败的具体原因仍未确定。用户随后要求正式发布并开启蜂鸣器，因此v1.0.0将默认自动音效打开，原有60ms短音及300ms声控保护逻辑未改。

正常游戏版已获用户实物确认，但蜂鸣器实际响声、合盖后的声学反馈、所有接口、ADC定量误差、调音精度及长时间丢块统计仍需按实验单验证。发布清单保留hardware_verified=false，表示整套硬件未全部验收；分别记录已验证的正常游戏和新增音效待确认范围。

SW1–SW4的硬件接法仍须返修；软件屏蔽故障键并不等于GPIO输入已验收。读保护选项字节未由此软件修改。详细资源占用、地址、依赖版本和文件校验值见发布包verification.json与manifest.json。
